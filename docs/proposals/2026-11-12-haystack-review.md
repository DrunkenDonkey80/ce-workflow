## Candidate ideas (for the accept/reject review)

1. **Warn before a hard run budget** (A3). Feed Haystack's token budget stop and last-steps reminder into the existing runaway-run plan `docs/plans/2026-09-27-001-fix-unbounded-direct-agent-runs-plan.md`: a reminder N steps before the cap, then a stop with a named reason. Measure with a bounded replay of the looping session.
2. **Prune old tool results in place before Ultrafull summarizes** (A1). Replace results older than the newest step and above a size floor with a "call `<tool>` again" placeholder; skip results already offloaded. Measure on the context-continuity benchmark and `scripts/audit-compaction.mjs`: tokens per compaction, summary quality, re-call rate.
3. **Tighten the compaction summary prompt** (A1). Add "copy identifiers (paths, IDs, commands, error strings) exactly" and "absence from this portion is not evidence something did not happen"; reject a summary that is not shorter than its input. Measure with `scripts/audit-compaction.mjs` before and after.
4. **Offload large non-bash tool results to a file** (A2). Per-tool size policy with a preview and pointer for subagent output, `browser_fetch`, jev results; leave inline when the write fails. Measure tokens per session on a browsing-heavy run.
5. **Directory-level agent rules** (A16). Move area-specific rules from the root `AGENTS.md` into the directory they govern, each written as rule plus reason. Only worth it if it cuts loaded context measurably; lowest priority.

## Out of scope (RAG and integrations)

- Document stores, retrievers, rankers, embedders: retrieval infrastructure, no counterpart.
- Converters, preprocessors, splitters: document ingestion.
- Readers, extractors, classifiers, routers, joiners: pipeline components for RAG flows.
- Pipeline graph engine (`core/pipeline` apart from breakpoints), serialization allowlists: Haystack's own runtime.
- Chat generator integrations and `docs-website/`: provider wrappers and docs site; Pi handles providers.
