## Merge with Astra (HR-04)

**Agreement: 9 of 16** areas have the same verdict (A2, A4, A6, A8, A9, A10, A11, A12, A15). A7 differs only in wording (ours Skip, Astra Already covered: Pi owns the loop either way). Each disagreement was checked in the code:

- **A1, ours Test first vs Astra Already covered → Test first.** Astra judged replacing our summarizer with Haystack's tiered or sliding-window compactor, which we also skip. It did not weigh the two narrow parts: Ultrafull really has no stripping (`extensions/work-models.ts:1775` returns early for every mode but Ultracompact; mode description `:222`), and our summary prompt (`extensions/work-compaction-memory.ts:238`) has no exact-identifier or absence rule.
- **A3, ours Test first vs Astra Adopt idea → Adopt idea.** The need is already proven by the overnight loop in `docs/plans/2026-09-27-001-fix-unbounded-direct-agent-runs-plan.md`; what is left is choosing limits, tested by replay. Astra's caveat is kept: a parent-session allowance does not cap subagents running on their own.
- **A5, ours Already covered vs Astra Test first → Test first.** Session logs back Astra up. Across local sessions, compaction entries record 744 `hybrid` and 106 `fallback` results (about 12% end in local fallback). The attempt errors carried in those entries are mostly `Memory budget exceeded` (791 mentions), then `unknown citation` (146) and `Invalid memory JSON` (141). Mentions are approximate because errors repeat across attempts and summaries. Today a validation failure retries the next model with the same task (`extensions/work-compaction-memory.ts:242-259`); the error is never fed back.
- **A13, ours Skip vs Astra Adopt idea → Skip.** Compaction outcome is already recorded per entry (`details.compactionMode`, fallback reasons, `tokensBefore`) and read by `scripts/audit-compaction.mjs:80`. Adding the same data to `plan3-stats` duplicates it. Counting fallback reasons in the audit belongs to the A5 trial's measurement.
- **A14, ours Skip vs Astra Adopt idea → Adopt idea.** Checked `scripts/benchmark-context-cache-live.mjs:130-137`: the summary averages only the runs that did not throw (`ok`), so a failed run disappears from the means. Only the exit code flags it. Baseline comparison under the Optimization Regression Rule is done by hand. A small compare step that pairs runs by repetition and shows missing or failed runs is cheap and protects every later trial.
- **A16, ours Test first vs Astra Already covered → Already covered.** Our idea (directory-level `AGENTS.md`) had no measured context problem behind it; the 76-line root file and existing rules suffice.

## Shortlist

Final Adopt idea or Test first, merged where one follow-up plan would touch the same code:

1. **Bound unattended runs with a warning before the stop** (A3, Adopt idea). A run allowance that persists across automatic continuations, one reminder a few steps before the limit ("N of M steps left, start wrapping up"; Haystack `hooks/budget/hooks.py:114-193`), then a pause with a named reason, never marking the plan complete. Feeds the open runaway-run plan. Measure by replaying the looping session: no new parent turn after the limit, below-limit work unchanged.
2. **Pair benchmark runs with the baseline and show missing ones** (A14, Adopt idea). Compare a candidate run file with the last accepted baseline by repetition, with runtime, total tokens, cost, turns and tool calls side by side; failed or missing runs shown as incomplete, never as zero. Check with synthetic reordered, missing and failed rows.
3. **Better compaction summaries: two prompt rules and error feedback** (A1 prompt + A5, Test first). Add "copy paths, IDs, commands and error strings exactly" and "absence from this portion is not evidence"; when the reply fails validation (most often over the size limit), retry once with the concrete error instead of the same task. Measure with `scripts/audit-compaction.mjs` (fallback rate and reasons, re-reads, repeated commands) before and after, then the end-to-end benchmark.
4. **Prune old tool results at the Ultrafull checkpoint** (A1 pruning, Test first). At compaction time only (rolling stripping would break the prompt cache), replace older large tool results with "call `<tool>` again if you need it", keep the newest step whole, and see whether the recent tail can keep more turns verbatim. Measure tokens per compaction, re-call rate and audit scores against the current Ultrafull.
5. **Save large non-bash tool results to a file with a pointer** (A2, Test first). Only for large outputs that cannot be cheaply re-run (subagent output, `browser_fetch`, jev): save first, then replace with a preview and path; a failed save leaves the result inline. Measure retrieval turns against the tokens saved; reject on an overall regression. Saved files may hold sensitive content, so they stay session-scoped.

## Out of scope (RAG and integrations)

- Document stores, retrievers, rankers, embedders: retrieval infrastructure, no counterpart.
- Converters, preprocessors, splitters: document ingestion.
- Readers, extractors, classifiers, routers, joiners: pipeline components for RAG flows.
- Pipeline graph engine (`core/pipeline` apart from breakpoints), serialization allowlists: Haystack's own runtime.
- Chat generator integrations and `docs-website/`: provider wrappers and docs site; Pi handles providers.
