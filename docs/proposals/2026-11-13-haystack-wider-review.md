## Candidate ideas (before measurement)

1. **K1 Measure and tune knowledge recall** (B1, B5). Judge a sample of injected recall blocks for relevance to the prompt, and count agent `knowledge` searches that returned facts the automatic recall had not injected. Tune only if either number is bad.
2. **W1 Main-content extraction for `browser_fetch`** (B3). Prefer `<main>` or `<article>` text, or a readability pass, over the whole body; keep the full text behind a flag.
3. **M1 Fallback chain for side models** (B2). `process_image` and the advisor try a second configured model on failure, as compaction does.
4. **E1 Faithfulness audit for compaction checkpoints** (B5). A script that judges each checkpoint claim against its cited records with a cheap classifier, reported next to `audit-compaction.mjs`.
5. **T1 Fast test set** (B6). A `verify:fast` that skips slow and live checks.

## Gap measurements (HW-03)

Session logs `~/.pi/agent/sessions/**/*.jsonl` modified since 2026-10-25 (727 files, about 50,700 assistant messages), entries deduplicated by id. Throwaway scripts in `%TEMP%/hs/`.

- **M1 side-model fallback: no gap.** `process_image` ran 50 times with 0 errors. Main-model errors: 80 `stopReason: "error"` messages; 55 were followed by more assistant work (Pi's own retry, `retry.maxRetries` 3, recovered them). 25 ended a run until the user wrote again: 14 network aborts, 7 Bad Request or expired token (a second model would not help), 4 usage-limit stops (one waited 171 minutes). A capacity fallback for the main model is possible through a Pi virtual model (`docs/virtual-models.md`: `route()` sees `reason: "retry"` and `failed.message.errorMessage`), but the gap is 4 stops in 19 days and switching provider loses the prompt cache.
- **W1 main-content extraction: small gap.** `browser_fetch` succeeded 15 times in 19 days (9 more failed on bot checks or refusals); real sizes from the "more characters trimmed" markers: median 19,900 characters, 90th percentile 37,600, total 343,000 (about 86k tokens over 19 days). Readability on 5 of those public pages kept 76% (Zephyr docs), 75% (Waveshare), 82% (blog), 27% (GitHub issue) of the body text; two pages returned no server HTML. Saving about a quarter of 86k tokens over 19 days is not material. `fetch_content` (pi-web-access, 56 calls, median 1,500 characters) already extracts main content for public pages.
- **K1 knowledge recall: real gap (precision, not recall).** Replaying `buildKnowledgeQuery` + `queryKnowledge` over every user prompt since 2026-11-01 (688 sessions, 1,897 prompts, only claims recorded before the prompt) injects recall on 1,800 prompts (95%), 2.67 claims on average (4,276 lexical, 531 path matches). Jev judged a spread sample of 29 turns: 14 had no useful claim; I spot-checked 6 and agree. Three noise sources: user-scope environment claims (the `/tmp` mapping, `aapt` path) match common words in any project; scheduled-timer messages (211 of 1,824 user messages, "⏰ Scheduled …") are not treated as machine text and get recall; 19 mostly-Cyrillic prompts lose all their words in the ASCII-only tokenizer (`tokens()`, line 655; Astra's finding). The 12 explicit `knowledge` searches all returned hits, so missing claims are not the problem.
- **E1 checkpoint faithfulness: no visible gap.** 711 compactions; a keyword screen ("forgot", "lost", "I said", "remember", …) of the 3 user messages after each found 16, none about a fact lost or changed by compaction (one is a Plan3 checkpoint overwriting a file edit, a different bug).
- **T1 fast tests: small gap.** 72 `npm run verify*` runs; 20 were full runs over a minute, 96 minutes in total over 19 days (about 5 minutes each, 7 failed). The Test Scope Rule already keeps the full suite to pushes; a faster set would save at most about 5 minutes a day.

## Shortlist

1. **K1 recall precision.** Gap: recall fires on 95% of prompts and about half of those turns carry no useful claim. Change: Unicode/NFC tokenizer for queries, scheduled-timer messages counted as machine text (the query then uses the last human request), and a higher match threshold for user-scope claims (they carry no project, so today a shared common word recalls them anywhere). Measure with the HW-03 replay before and after; keep only what lowers the no-useful share without losing the 12 known-good searches.
2. **Verifier omission.** Add `test-audit-compaction.mjs` to the `verify-package.mjs` list. One line.
