# Independent desk review: what ce-workflow should borrow

**Start with the evidence used to make decisions:** calibrate the judges, show what the benchmarks cannot establish, and stop counting missing prices as zero. None of these requires a second agent loop. The citations below are relative to each repository at the stated pin; the measurements in the ranking are proposed checks, not results.

## Top seven, in implementation order

1. **Calibrate the judges (S6).** Start with paired examples that differ in just one fact: an agent asks the user to run an available check versus asks for a physical action it cannot take. Label them independently of the judge, freeze an assessment split, then run the actual handoff and design judges on every judge-model or rubric change. Report the confusion matrix, abstentions and repeat disagreement on held-out items, not agreement on tuning examples.
2. **Make small benchmark results honest (S5).** Extend `compare-benchmark-runs.mjs` with distinct cases, complete pairs, both directions of changed outcome, unscored/error counts and a “not established” line. Test with a saved comparison containing duplicate reps, a judge timeout and an inapplicable metric: none may increase the number of independent cases or become a quality failure. Publish per-arm case-level intervals only for defined binary outcomes; keep runtime, tokens, cost, turns and tool calls alongside them.
3. **Preserve the first failure in the hub (L6).** Retain a bounded per-turn diagnostic summary at the RPC/session boundary and offer a redacted export on failed or interrupted turns. Replay first-error-then-disconnect, user stop, steering and unexplained exit fixtures; score correct cause or explicit unknown, first-error retention and zero secret canaries in exports. On real failures compare time to a useful diagnosis with notices alone.
4. **Measure reviewer restraint (B2).** Add ordinary paired diffs to the skills lab: for example, a correct inclusive limit and a one-line off-by-one regression, with the boundary requirement identical. Benchmark the diff reviewer with and without the review skill on blinded cases; require fewer false flags on correct diffs **and** no loss of genuine detections on matched coverage, reporting unscored cases, cost and turns.
5. **Show pricing coverage (L7).** In Plan3 stats and lab metrics, count replies with an explicit finite cost separately from all replies with usage, and mark incomplete totals as partial in comparisons. Check fixtures with priced zero, absent cost and mixed-model amounts: the known subtotal must be unchanged, but only the complete fixture may be presented as a full cost. Count partial comparisons in existing runs before investing in price lookup.
6. **Warn about invisible instructions before review (S8).** Scan third-party instruction text locally in `work-extension-scout.ts` before sending it for assessment. Measure detection and precise locations on hidden-tag and directional-control fixtures, and false warnings on ordinary RTL prose and emoji sequences; check that neither logs nor model input reproduce suspicious controls unescaped.
7. **Pilot a tool-backed completion gate (L2).** For a small set of Plan3 steps with a declared test, link the step to its tool invocation and result; a failed check permits one repair, then parks the step with the evidence. Compare against text-only checks on matched tasks including failing and flaky cases: count false completions, false blocks, verified completions, runtime, tokens, cost, turns and tool calls across continuations. Expand only if enough real steps have an unambiguous check and the reliability gain holds at acceptable cost.
