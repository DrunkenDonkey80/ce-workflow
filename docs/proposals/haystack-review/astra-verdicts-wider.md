## Ranked top ideas

### 1. Make offline test coverage explicit and run it automatically — Adopt idea

**Concrete change:** Add `test-audit-compaction.mjs` to the verifier’s existing list. Account explicitly for root test scripts that are included or intentionally live-only, then add a credential-free CI job on `master` pushes and relevant pull requests; make a successful check a prerequisite for app publication. Begin with the existing package runner, verifying its clean-runner dependencies rather than assuming every local test is portable.

**Cheap gap measurement first:** Compare the root test inventory with `scripts/verify-package.mjs:115–121`. The code already demonstrates one deterministic omission and one intentionally unsuitable live test; inspect the remaining scripts for credentials, global installations and device requirements, then time the offline selection in an isolated environment. Record excluded tests and their reasons.

**Check:** The supervisor should run `node scripts/test-audit-compaction.mjs` and a small discovery-accounting test after implementation. Run the configured CI selection once on a clean runner; do not add full-suite execution after every local edit.

### 2. Stop dropping non-ASCII knowledge queries — Adopt idea

**Concrete change:** Update only the retrieval tokenizer in `extensions/work-knowledge.ts` to normalize NFC and recognize Unicode letters, combining marks and numbers. Preserve ASCII identifier boundaries, existing English behavior, path/symbol bonuses and the two-token eligibility rule. Leave persistent claim deduplication unchanged: it uses a separate tokenizer and changing it can merge records.

**Cheap gap measurement first:** A static repro is sufficient to establish the defect: the query `цветова схема`, with no explicit paths or symbols, produces no tokens and returns no results, even with an identical live claim. Separately, locally sample human prompts and live knowledge records to count non-ASCII queries and label a small set of expected matches; this establishes prevalence without exposing their text.

**Check:** Add Cyrillic exact-text, composed/decomposed accent, mixed identifier and unrelated-query cases. Run:

- `node scripts/test-work-knowledge.mjs`
- `node scripts/test-work-knowledge-retrieval.mjs`

Compare recall, reciprocal rank and unrelated-result rate. Do not claim that this small change solves cross-language synonyms or CJK segmentation.

### 3. Audit summary claims against their actual evidence — Test first

**Concrete change:** Add an offline semantic audit alongside `scripts/audit-compaction.mjs`, borrowing the blind-label approach from `scripts/skills-lab-judge.mjs`. Judge atomic claims against source excerpts and report unsupported claims, contradicted claims and missing still-applicable requirements separately. Require evidence references and explicit judge failures; keep this out of the live compaction path initially.

**Cheap gap measurement first:** Have the supervisor run `node scripts/audit-compaction.mjs --top=10`. Manually inspect several high-signal compactions and a random comparison sample from `~/.pi/agent/sessions/**/*.jsonl`, matching summaries to the correct session branch and preceding evidence. Count unsupported assertions and omitted requirements separately: a summary can be entirely faithful yet omit crucial information.

**Check:** Trial the judge on human-labeled examples, including invented citations, real citations supporting the wrong claim, superseded instructions and accurate-but-incomplete summaries. Measure agreement, false alarms, failure rate and cost before using the score. Existing judge bundles redact experimental-arm identifiers, **not necessarily secrets**; apply secret redaction and review excerpts before any provider call.

### 4. Extract main page content before the browser text cap — Test first

**Concrete change:** Trial a conservative article/main-content extraction path inside `browser-fetch/extension/background.js`, retaining whole-body fallback. Preserve code, tables, title, final URL, links, existing approval behavior and the untrusted-content warning; do not silently discard the original evidence. No new HTTP fetcher or general document store is needed.

**Cheap gap measurement first:** Sample existing `browser_fetch` tool results from session logs. Count truncation markers, repeated navigation text, answer-bearing passages lost behind boilerplate, and immediate follow-up fetches for the same information. Logs can identify candidates but cannot reconstruct DOM structure; use a small, approved page sample for a saved-DOM comparison before implementing extraction.

**Check:** Compare retained answer-bearing content and code/table fidelity, output size, extraction latency and follow-up tool calls. Reject a smaller-output result if it drops relevant content. Keep heading-aware splitting deferred unless this sample shows that extraction alone leaves a material long-page problem.
