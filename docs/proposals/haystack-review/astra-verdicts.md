## Review

- **Correct:** ce-workflow already covers most of Haystack’s useful architectural mechanisms. The strongest opportunities are bounded unattended execution, better comparison reports, and narrowly scoped reliability experiments—not another agent framework.

## Ranked top 5 ideas

### 1. Bound unattended execution — A3, Adopt idea

**Concrete change:** Extend the existing Plan3 night integration at `extensions/plan3.ts:1199` with a user-approved parent-session LLM-step allowance. Persist consumption across automatic continuations, issue one near-limit reminder, and pause with an explicit budget reason when exhausted; never mark the plan complete because the allowance ended. Enforce it at safe turn boundaries and before further automatic scheduling.

**Measure:** Replay deterministic event sequences covering exhaustion, continuation, restored sessions, cancellation, and simultaneous completion. Assert that no new parent-model turn is scheduled after exhaustion and that ordinary below-limit work is unchanged. Record completion rate, stopping latency, and observed usage; explicitly exclude independently running children from the guarantee.

### 2. Compare benchmark rows by stable identity — A14, Adopt idea

**Concrete change:** Extend `scripts/benchmark-context-cache-live.mjs` reporting to compare baseline and candidate results by scenario and repetition identity. Show each outcome and its runtime, total provider tokens, cost, turns, and tool calls; preserve failed or missing rows as explicit incomplete comparisons. Reuse the existing all-session usage aggregation rather than introducing an evaluation framework.

**Measure:** Add synthetic report checks for reordered rows, missing trials, failures, duplicate identities, and unequal repetition counts. Reordering must not change paired deltas, and missing data must never appear as zero cost or successful improvement. Validate the report against manually summed existing artifacts.

### 3. Record why compaction happened and how it ended — A13, Adopt idea

**Concrete change:** Extend the bounded local statistics in `extensions/plan3-stats.ts` with compaction trigger, mode, elapsed time, success/failure/fallback, and available before/after size measurements. Populate these from existing compaction events and results in `extensions/work-models.ts`; label estimates as estimates. Store no transcript, tool arguments, or new external telemetry.

**Measure:** Exercise successful, failed, fallback, and cold-cache compactions and assert exactly one matching outcome record per operation. Check that log growth stays bounded and fixture secrets never appear. Compare instrumented and uninstrumented end-to-end runs for runtime, tokens, cost, turns, and tool calls; improved diagnosis is the intended benefit, not assumed speedup.

### 4. Preserve exact recoverability when shortening transient results — A2, Test first

**Concrete change:** Trial session-scoped text offloading at the existing giant-result shortening boundary in `extensions/work-models.ts`, initially only for selected non-reproducible outputs. Save the original successfully before substituting a preview and readable file pointer; leave errors and failed writes untouched. Retain the grace period, avoid double-offloading Pi’s existing overflow files, and keep image handling separate.

**Measure:** Compare normal coding tasks with tasks that later need the omitted middle of an output. Measure exact recovery, additional reads, rerun commands, task correctness, and the complete runtime/token/cost/turn/tool-call totals. Test failed writes, session separation, cleanup, and preservation of the sole recovery pointer; reject the policy if retrieval overhead creates an overall regression.

### 5. Trial bounded validation-feedback repair for compaction JSON — A5, Test first

**Concrete change:** In a benchmark-only variant of `compactMemory()` in `extensions/work-compaction-memory.ts`, compare the current selected-model → current-model fallback with selected-model → one validation-feedback repair. Keep both variants within two calls and the same total deadline, preserve local evidence fallback, and retry only output-validation failures—not cancellation, authentication, or transport failures. Keep citation validation unchanged.

**Measure:** Replay the same malformed-output and real compaction cases through both variants. Count accepted valid summaries, unknown citations, retained constraints, fallback frequency, and downstream re-reads or corrections—not JSON validity alone. Run the same end-to-end benchmark and include every summarizer attempt and continuation in runtime, provider tokens, cost, turns, and tool calls.

### Acceptance boundary

Use **Ultrafull** for ordinary live comparisons; use **Ultracompact** only for its specific stripping behavior. Compare against the last accepted baseline and revert material overall regressions. The supervisor should run `node scripts/test-work-compaction.mjs` for changes touching retention or compaction memory, plus focused checks for each new behavior; paid end-to-end trials remain separate from this desk review.
