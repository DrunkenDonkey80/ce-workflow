## Goal, requirements, and non-goals

- Add optional, project-enabled Jev tools for multi-file relevance triage, evidence selection, and classification of arbitrary supplied JSON state. They work in ordinary sessions, including Plan3; no work item or autonomous workflow is required.
- Reuse Pi's classifier support and OpenRouter login. Keep ordinary read/search/symbol tools available; the main model chooses whether Jev is useful.
- Return compact typed answers and genuine source anchors, not full file dumps. Support multiple questions sharing state, independent per-file queries, and explicit small cross-file bundles.
- Benchmark actual agent behavior with tools available versus unavailable, using the real AI-Wedge investigation as the source case. Include classifier overhead and all continuations, not just apparent reductions in returned text.
- Preserve unrelated dirty files in both repositories. Develop on existing `master`; no branch switch, automatic commit/push, work-item operations, background verifiers, or automatic delegation.

Non-goals: replacing exact search/LSP/compilers, free-form Jev summarization or extraction, security/permission decisions by classifier, shell execution outside Pi's own `bash` tool path (D08 allows `jev_ask` commands only through it), automatic compaction or any change to existing compaction behavior (the D08 advisor only prints a note), global interception of reads, a retrieval database, a new provider/auth implementation, semantic caches, workflow routing, or changing the compaction/research/Plan3 work already in progress. Full coding/build/phone replay is excluded from the first benchmark.

## Decisions

- D01 — **Reuse Pi login for OpenRouter credentials.** Jev settings show enable/disable and credential status and direct the user to native `/login`; no API keys in ce-workflow settings and no second credential store. Rationale: Pi already authenticates native classifiers, while ce-workflow settings can be exported to the clipboard. Source: user planning `ask_user` answer, “Reuse Pi login (recommended)”.
- D02 — **First comparison is a read-only AI-Wedge investigation.** Compare the same source snapshot/question with and without optional Jev tools, allowing the main model to choose tools. Measure correctness, total provider tokens/cost, runtime, turns, and calls. Rationale: the original task later built Android and used a physical phone; a reproducible investigation does not prove full implementation savings. Source: user planning `ask_user` answer, “Read-only investigation first (recommended)”.
- D03 — **Per-project opt-in, default off.** Global OpenRouter credentials do not enable any project. Rationale: selected code/log snippets leave the machine for OpenRouter/TypeSafe; enabling one repository must not enable others. Source: user planning `ask_user` answer, “Per-project opt-in (recommended)”.
- D04 — **Native runtime, two thin tools, one shared helper.** Use `ctx.modelRegistry.getModelOfType()` / `getAvailableOfType()` / `classify()`, not the demo's HTTP client or copied extension stack. Proposed names: `jev_triage` and `jev_evidence`. Rationale: the installed public API already provides auth, provider transport, cancellation options, typed results, and usage. Source: installed Pi documentation/types and source research; implementation choice, not a separate user answer.
- D05 — **Code supplies evidence; Jev classifies it.** Jev returns bool probabilities, declared choices, or scores, not arbitrary quotes/symbols/line numbers. Code creates candidate IDs, paths, line ranges, hashes, and excerpts. Main-model direct reads remain required before editing/quoting source. Rationale: source and Opus review agree classification is not extraction; classifier opinions cannot establish absence. Source: upstream types, native classifier docs, Opus report.
- D06 — **Experimental, reporting-only comparison.** Default off remains regardless of mock tests. A smaller main-model context alone is not success; regressions in the complete paired investigation cannot be rationalized by that submetric. Benchmark results do not authorize code changes, automatic rollback, or promotion. Source: project Optimization Regression Rule, the comparison request, and superseding D07.

This switch controls **these new tools**, not Pi's pre-existing native `models.classify()` facility or unrelated tools. Do not advertise it as a system-wide data-exfiltration firewall.

### `jev_triage`

One JSON request contains `jobs`, at most 32. Each job has a unique `id`, a native typed `questions` map (up to 32 questions), optional JSON `state`, and optional explicit file/range `sources`. Code reads sources inside the project and assembles one state per job. One job with several sources is the explicit cross-file form; separate jobs cannot establish cross-file relationships. A 20–30-question map shares one state/provider invocation rather than rereading state for every question.

Use native `bool`, `choice`, and `score` schemas; reject invalid question IDs/types/options before file access or provider calls. Validate JSON depth/size and native criteria constraints. Source entries carry `path` and optional inclusive `startLine`/`endLine`; reads must describe whether the whole file or only a range was supplied. Paths alone yield file anchors, never fabricated evidence lines.

Return per-job status, typed answers, compact probability/confidence information, supplied-source anchors/hashes, actual model, and aggregate usage/coverage. Preserve raw probabilities; initial 0.2/0.8 bool bands may label unlikely/uncertain/likely but are uncalibrated heuristics, not proof. A choice can only select caller-declared labels. Free-form exact extraction requests should use ordinary tools instead.

### `jev_evidence`

Provide repository candidate retrieval plus optional semantic classification without having the main model print the candidate bodies first. Accept explicit relative file/directory scopes or globs, an optional bounded search pattern (literal by default; explicit regex mode), typed questions, and `unit: file | window`.

Code enumerates bounded candidates, honoring ignore rules and exclusions, then constructs real file or matched-line windows with stable IDs. Windows include their exact `path`, line range, content hash, and locally captured excerpt. Jev classifies the supplied candidates; code selects a bounded ranked result set and returns actual excerpts from the same captured bytes. No generated quotes, line numbers, or hidden additional model loop. Oversize files require narrowed ranges/windows; do not pretend a clipped prefix is the complete file. Cross-file questions belong in an explicit `jev_triage` bundle.

Reuse existing search/path utilities where actually suitable; otherwise use `rg` through argument-array process execution with `shell: false`, `--` before user patterns/paths, bounded output and timeout. No arbitrary `command` parameter or flags passed through from the model. Missing `rg`, malformed regex, no matches, skipped files, provider errors, and incomplete scans remain distinguishable.

### Shared limits, privacy, and failure behavior

- Start with concurrency 4, at most 32 classifier invocations per tool call, 30-second per-request and 120-second overall deadlines, all joined to the tool abort signal. Do not layer an independent retry loop over native transport. Stop scheduling on abort/budget exhaustion; retain completed results and usage with explicit incomplete coverage.
- Budget the entire serialized state **and questions**, not file text alone. Initial conservative UTF-8 cap per invocation: `min(24_000, floor(model.contextWindow * 0.75))` bytes, with fixed envelope accounted for. This is deliberately conservative, not an exact token estimate. Reject an oversized indivisible job with narrowing guidance. Bound candidate enumeration/output too; suggested maximum 128 enumerated candidates, 32 classified, 10 returned excerpts, and 24,000 output bytes. Report every cap and omitted count. No silent alphabetic selection described as an exhaustive search.
- Resolve project root and source paths canonically, verify containment after realpath, reject symlink/junction escapes, traversal, device paths, binary/NUL data, and unexpected file changes during capture. Normalize displayed relative paths across Windows/POSIX; return absolute read paths when useful.
- Exclude `.git`, dependency/build/cache/session directories, auth/settings credential files, `.env*`, private keys/certificates, keystores, `local.properties`, `google-services.json`, and recognizable secret-bearing content before upload. Skip suspicious inputs rather than silently changing their meaning. Restrict inputs to explicit scopes; denylisting is defense in depth, not a guarantee that arbitrary files contain no secrets.
- No raw file states, credentials, or provider response bodies in custom logs, stderr, errors, or result details. File-loading requests contain paths/ranges, not raw source. Caller-supplied inline JSON is already part of the ordinary tool-call transcript; document that limitation. Return only bounded selected evidence and sanitized errors. No custom raw-exchange recorder.
- Treat file/log instructions as untrusted data. Classifications cannot authorize actions, certify tests, dismiss risks, or establish repository-wide absence. Zero deterministic matches means only “no matches for these patterns in this fully specified scanned scope,” not semantic absence.
- Errors/aborts are not negative answers. A partially failed evidence query reports incomplete coverage and directs normal read/search fallback. Stale hashes require a fresh read. Hidden classifier reads do not satisfy the main agent's read-before-edit requirement.
- Report native classifier usage on the enclosing tool result once. Account for failed attempts when the runtime supplies usage; mark unavailable billing as unknown, not zero. Avoid double counting nested tool usage or codemode aggregation. No dollar promises derived solely from the demo's hard-coded price.
